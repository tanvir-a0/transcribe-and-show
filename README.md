# Live Procedural Music Visualizer

A fully automated, AI-driven, real-time procedural music visualizer for a 128x64 monochrome OLED display driven by an ESP32.

Feed it a YouTube link or a local audio file. It transcribes the song with OpenAI's Whisper to get millisecond-accurate word timings, an LLM writes the graphics engine from a generated prompt, and the result is hot-loaded and streamed to the OLED perfectly in sync with the music — every lyric word rendered on top of its own unique procedural animation.

The creative code is **not** hand-written. It is generated by an LLM, per song, from a prompt this project builds for you.

## Architecture

**1. AI Audio Transcription — `generate_timeline_whisper.py`**
Downloads audio from YouTube (`yt-dlp`) or takes a local media file. Runs Whisper with `word_timestamps=True` to produce `timeline.json`: a flat list of `word` and `gap` events with exact start/end times. Gaps are inserted wherever there is more than 1s of silence. It also writes `llm_prompt.txt`, a song-specific prompt for Step 2.

**2. LLM Procedural Art — `generated_visuals.py`**
You paste `llm_prompt.txt` into an LLM and save its answer as `generated_visuals.py`. The module exposes one function:

```python
def render_frame(current_time, current_event) -> PIL.Image  # 'L' mode, 128x64, values 0 or 255
```

**3. Live Stream Engine — `live_streamer.py`**
Reads `timeline.json`, hot-loads `generated_visuals.py`, syncs to wall-clock audio time, packs each frame into the SSD1306 page format, and streams it over serial at 1,000,000 baud — while mirroring the output in an OpenCV preview window.

**4. ESP32 Firmware — `node_code/`**
Bare-metal I2C driver (no display library) that receives the binary stream and blits it straight to the panel.

## How the visuals avoid repetition

This is the hard part of the project, and it lives entirely in the generated prompt (`PROMPT_TEMPLATE` in `generate_timeline_whisper.py`). Two specific failure modes are designed out.

**Seeding on the word *and* its timestamp.** Lyrics repeat heavily — this song has 461 words but only 104 unique ones, and 92% of all words are repeats (`"been"` is sung 28 times). Seeding on the text alone made every repeat pixel-identical, so each chorus was a literal replay. The prompt mandates:

```python
seed = int(hashlib.md5((text + "|" + str(current_event.get("start", 0))).encode()).hexdigest()[:8], 16)
```

Result: **460 distinct seeds across 461 words.**

**Sixteen structurally different effect families, not one effect with random parameters.** Varying the node count and rotation speed of a single spinning polygon is invisible at 128x64 — a 5-sided polygon at radius 18 and a 6-sided one at radius 24 look the same. So the prompt demands separate render functions producing fundamentally different *kinds* of image, dispatched by the seed:

| | | | |
|---|---|---|---|
| plasma | tunnel | metaballs | wireframe |
| particles | fractal | scanbands | kaleido |
| automaton | typo | lightning | floor |
| voronoi | bars | moire | ripple |

All 16 are exercised across the song (21–37 words each). Six separate `gap_*` scenes cover instrumental breaks, rotating every 4 seconds so a long break never sits on one image.

The prompt also enforces the rules that actually make variety *readable* on a 1-bit panel:

- **Don't center everything at (64,32).** Sixteen effects that are all centered symmetric blobs still read as one effect. Half must be full-frame, off-center, or edge-anchored.
- **Vary polarity.** A third of the families draw black-on-white. On a mono display this is the single largest perceived difference between two frames.
- **Dither instead of wireframe.** Per-pixel float intensity thresholded against a 4x4 Bayer matrix gives real gradients and shading; 1-pixel lines shimmer and look sparse at this resolution.
- **Evolve within the word.** Effects are driven by `progress = (current_time - start) / (end - start)`, with a hard visual attack in the first ~100ms so each word lands on the beat.

## Hardware

ESP32 DOIT DevKit v1 + a 128x64 I2C OLED (SSD1306 or SH1106).

| OLED | ESP32 |
|------|-------|
| VCC  | 3V3   |
| GND  | GND   |
| SDA  | GPIO 21 |
| SCL  | GPIO 19 |

I2C address `0x3C` at 400kHz Fast Mode. Pins and address are at the top of [`node_code/src/main.cpp`](node_code/src/main.cpp).

## Installation

Python 3 and PlatformIO are required.

```bash
pip install -r requirements.txt
```

`ffmpeg` must also be on your PATH (Whisper decodes audio with it, and yt-dlp uses it to extract MP3). Node.js is needed only for YouTube downloads, where yt-dlp runs a JS challenge solver to get past YouTube's anti-bot protection:

```bash
choco install ffmpeg nodejs -y
```

Flash the firmware:

```bash
pio run -t upload -d node_code
```

The OLED shows a `Hello, World!` splash on boot, which confirms wiring before you stream anything.

## Usage

**Step 1 — Generate the timeline and prompt**

```bash
python generate_timeline_whisper.py
```

Paste a YouTube link, or leave it blank to pick a local `.mp3`/`.mp4`. Then choose a Whisper model size (`tiny`/`base`/`small`/`medium`/`large`); larger is much more accurate on music, and CUDA is used automatically when available. Outputs `timeline.json` and `llm_prompt.txt`.

**Step 2 — Generate the art**

Paste the contents of `llm_prompt.txt` into an LLM and save the Python it returns as `generated_visuals.py` in this folder.

**Step 3 — Stream it**

```bash
python live_streamer.py
```

Set `COM_PORT` at the top of [`live_streamer.py`](live_streamer.py) to match your board. The script waits for the ESP32's ready byte, then prompts you — press `ENTER` at the exact moment you hit play on the song. Press `Q` in the preview window to stop.

## Serial protocol

1,000,000 baud, with a per-frame handshake so the stream can never desync:

| Direction | Bytes | Meaning |
|-----------|-------|---------|
| ESP32 → PC | `K` | Booted, ready for frames |
| PC → ESP32 | `0xAA 0x55` + 1024 bytes | Frame header + SSD1306 page-packed payload |
| ESP32 → PC | `K` | Frame drawn, send the next one |

The payload is built by `pack_to_ssd1306_format()`: the 64x128 binary frame is reshaped into 8 pages of 8 rows and collapsed into bytes with a `[1,2,4,8,16,32,64,128]` weight vector — a vectorised numpy operation, no per-pixel loop.

## Performance

Measured on the full 461-word timeline:

| | |
|---|---|
| Word frame render | **7.1 ms** (~141 fps ceiling) |
| Gap frame render | **0.4 ms** |

Rendering is not the bottleneck; the I2C write and the serial handshake are. Fonts are cached at module level and numpy coordinate grids are precomputed once, which is what keeps per-frame cost flat.

## Troubleshooting

**The image is shifted 2 pixels sideways.** `drawFrame()` sends a column offset of `0x02` for SH1106 panels. On a true SSD1306 change it to `0x00`.

**`Failed to connect to COM8`.** Fix `COM_PORT` in `live_streamer.py`, and close any serial monitor holding the port — including PlatformIO's.

**Visuals drift out of sync with the song.** Timing is anchored to the `ENTER` keypress, not to the audio file, so an early or late press offsets the whole run. Restart and press it on the first beat.

**`generated_visuals.py` throws.** `render_frame` wraps each family in a try/except that falls back to `fx_plasma`, so a bad family degrades instead of crashing. A traceback in the console means the failure is outside those handlers.

**OpenMP duplicate library error.** Already handled — `KMP_DUPLICATE_LIB_OK` is set at the top of `generate_timeline_whisper.py` for Conda environments with both PyTorch and OpenCV.
